knowledge to a software QA scenario, rather than simply recalling knowledge,

## NONDETERMINISM AND SOFTWARE QA
* Be able to explain what nondeterministic software is.
* Be able to explain why nondeterminism makes it hard to do requirements
  verification, even for one input.
* Be able to explain why nondeterminism makes it hard to debug defects.
* Be able to describe the process through which memory errors can lead to
  nondeterministic software.
* Be able to define what a data race (race condition) is and explain why it
  can lead to nondeterministic software.
* **Be able to identify testing situations where a memory related bug is not caught by ASAN at runtime and explain why.**
* **Be able to identify testing situations where a data race bug is not caught by TSAN at runtime and explain why.**
* **Be able to use ASAN output to locate a memory error and explain why it is an error.**
* **Be able to use TSAN output to locate a data race error and explain why it is an error.**
